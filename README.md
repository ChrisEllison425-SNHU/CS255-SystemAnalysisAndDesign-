# CS255-SystemAnalysisAndDesign-
This is a repository for SNHU class CS255-SystemAnalysisAndDesign 

**1. Project Summary**
DriverPass was a project for client Liam, with Ian serving as the IT Officer. They wanted a secure, cloud-based web application that would allow customers to purchase training packages, complete online courses and practice tests, and schedule driving lessons. Staff would manage customers, instructors, vehicles, appointments, payments, and reports.

**2. What I Did Well**
I did well at identifying the major functional and nonfunctional requirements. I focused on security, role-based access, scheduling controls, reporting, payment processing, and cloud infrastructure. I also made sure the design supported both customers and employees.

**3. What I Would Revise**
I would revise the system requirements to make them more specific and measurable. For example, I could define expected response times, availability targets, and clearer acceptance criteria for important functions such as scheduling and authentication. This would make the requirements easier to test and validate.

**4. Understanding User Needs**
I interpreted the users' needs by separating the system into customer, staff, and administrative functions. I used those needs to determine features such as account management, lesson scheduling, online training, progress tracking, reporting, and role-based permissions. Considering user needs is important because the system must solve the actual problems users experience and be easy, secure, and practical for them to use.

**5. Approach to Software Design**
I would begin by identifying stakeholders, gathering requirements, and defining the system's goals and constraints. Then I would use use cases, process diagrams, data models, and prototypes to understand how the system should work. In the future, I would continue using iterative design, validating requirements with users, identifying security and performance needs early, and testing the design against realistic user scenarios.
